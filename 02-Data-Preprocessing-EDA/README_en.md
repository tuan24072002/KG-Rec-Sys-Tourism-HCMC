### 🗺️ Administrative Boundary Ontology Mapping (New Ward/District Merger in HCMC)

#### 1. Administrative Context

In recent years (specifically in 2021 and the 2024-2025 transition period), Ho Chi Minh City has undergone major administrative restructuring of its districts and wards:

- **District Merger:** Districts 2, 9, and Thu Duc were merged into **Thu Duc City** (a municipal city equivalent to a district level, eliminating the previous sub-districts).
- **Ward Merger:** Multiple old wards merged to form new wards (e.g., *Vo Thi Sau Ward* in District 3 was merged from Wards 6, 7, and 8; *An Khanh Ward* in Thu Duc City was merged from Binh An, Binh Khanh, and old An Khanh wards, etc.).

#### 2. Ontology Design in Graph Database (Neo4j)

To preserve the historical record of POIs (Point of Interests) while maintaining alignment with modern administration, we model the administrative boundary ontology as follows:

##### Nodes (Entities):

- `(d:District)`: Direct sub-municipal district/city (e.g., `District 1`, `District 3`, `Thu Duc City`).
- `(w:Ward)`: Ward/Commune (attributes: code `ward_code`, name `name`, province code `province_code`).

##### Relationships:

1. **`(w:Ward)-[:BELONGS_TO]->(d:District)`**: Defines which district/city a ward belongs to.
2. **`(poi:Poi)-[:LOCATED_IN]->(w:Ward)`**: Connects a POI to its **historical/original** ward when the data was scraped.
3. **`(old_w:Ward)-[:MERGED_TO]->(new_w:Ward)`**: Describes the ward merger history (e.g., `Ward 12` merged to `Hoa Hung Ward`, `Binh An Ward` merged to `An Khanh Ward`).

##### Relationship Diagram:

```
  (poi:Poi) -[:LOCATED_IN]-> (w_old:Ward) -[:MERGED_TO]-> (w_new:Ward) -[:BELONGS_TO]-> (d_new:District)
                                 |
                           [:BELONGS_TO]
                                 v
                            (d_old:District)
```

#### Preprocessing & Address Normalization Pipeline

The preprocessing step parses raw addresses in `poi_info.csv` and preserves the old address representation while linking nodes accurately:

1. **District/Ward Extraction:**
   - Employs regex key terms to match districts and wards (even with abbreviation or unaccented letters).
   - Maps old districts to `Thu Duc City` if they were located in District 2, 9, or Thu Duc.
2. **Address Preservation:**
   - Normalizes and formats the address to the **old address format** stored in the POI's `address` attribute: `[Street address], Ward [Old], District [Old], Ho Chi Minh City`.
   - Links the POI to the **old ward code** using the `LOCATED_IN` relationship.

#### Querying Old vs. New Address via Ontology

To dynamically retrieve both the old and new address of a POI, we traverse the ontology in Neo4j. The target formats are:
- **Old Address Format:** `Street address, ward, district, city`
- **New Address Format:** `Street address, ward (new), city`

##### Example Cypher Query:
```cypher
MATCH (poi:Poi)-[:LOCATED_IN]->(old_w:Ward)
MATCH (old_w)-[:BELONGS_TO]->(old_d:District)
OPTIONAL MATCH (old_w)-[:MERGED_TO]->(new_w:Ward)
WITH poi, old_w, old_d, coalesce(new_w, old_w) AS active_w
MATCH (active_w)-[:BELONGS_TO]->(active_d:District)
WITH poi, old_w, old_d, active_w, active_d,
     replace(poi.address, ", " + old_w.name + ", " + old_d.name + ", Thành phố Hồ Chí Minh", "") AS street_part
RETURN poi.name AS TenPOI,
       poi.address AS DiaChiCu,
       street_part + ", " + active_w.name + ", " + 
       case when active_d.name = 'Thành phố Thủ Đức' then 'Thành phố Thủ Đức, Thành phố Hồ Chí Minh' else 'Thành phố Hồ Chí Minh' end AS DiaChiMoi
LIMIT 10
```
